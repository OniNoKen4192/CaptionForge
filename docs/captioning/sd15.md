# Captioning for SD 1.5 LoRAs

> Read [00-principles.md](00-principles.md) first. This doc only covers what's
> specific to vanilla Stable Diffusion 1.5 (not the anime SDXL forks).

## TL;DR

**Tag-based, short, comma-separated.** SD1.5 has a single, relatively weak text
encoder (CLIP-L) that responds to keyword bags, not prose. Caption in Danbooru/booru
style: `trigger, full body, standing, neon lighting, alley, night`. Legacy model,
but still a fast and forgiving LoRA target.

## 1. Caption style

- **One text encoder: CLIP-L (ViT-L/14).** It's the same encoder SDXL also uses as
  its *smaller* half — small and prose-averse. Reliable attention falls off well
  before the 75-token window fills (research estimates ~20 tokens of *dependable*
  comprehension).
- **Community default is tag-based** comma captions. Natural language *works* but
  gives you less granular prompt control and wastes the encoder's strengths.
- Keep it within ~75 tokens (one CLIP chunk). You rarely need more for SD1.5.

## 2. Caption format & ordering

- Separator: comma + space. One `.txt` per image, matching basename.
- **Order matters** — earlier tags carry more training weight. That's why
  `keep_tokens` / `shuffle_caption` exist.
- **Trigger first, in every file.** Then booru-ish order: subject/trigger →
  variable attributes → clothing → pose/expression → background → framing → style.
  You don't need to be rigid; `shuffle_caption` reorders the non-kept portion anyway.

## 3. Trigger word handling

- Rare/unique token at the **front** of every caption (see principles for token
  choice). `keep_tokens = 1` pins it; enable `shuffle_caption` for the rest.
- **Class token** (`woman`, `dog`) is only really needed with regularization images.
  For a plain LoRA it's optional.
- `caption_dropout_rate ~0.1` is a reasonable starting point. SD1.5 supports the full
  shuffle/dropout suite (unlike some older SDXL builds).

## 4. Length & detail

Short. Trigger + the handful of *variable* tags — often 5–15 tags for a character.
Apply the omit-to-bake-in rule (principles §"caption what you want to vary"). Heavy
captioning dilutes likeness on a character set; styles and objects tolerate more.

## 5. Do / Don't

**Do**
- Caption in tags. Trigger first, identical form everywhere.
- Caption the variables (background, pose, expression, outfit, framing).
- `keep_tokens = 1`, `shuffle_caption = on`.
- Hand-check a few `.txt` files — auto-taggers lie.

**Don't**
- Don't write flowery paragraphs — CLIP-L won't use them, and you waste tokens past 75.
- Don't caption the identity traits you want the trigger to own.
- Don't reuse `sks`/`ohwx` blindly — overexposed; pick a fresh token.
- Don't expect a class token to do anything without regularization images.

## 6. Worked example

Character "Mara" — short silver hair + facial scar are part of her identity. Token
`m4ra`. Image: full-body, neon alley at night, arms crossed, smirking, leather jacket.

```
m4ra, full body, standing, arms crossed, smirking, black leather jacket, neon lighting, alley, night
```

- `m4ra` first and identical everywhere (`keep_tokens=1`).
- **Silver hair and scar omitted** → baked into `m4ra`, reproduced reliably.
- Jacket, pose, expression, setting, lighting, framing **captioned** → decoupled and
  controllable later (prompt her in a red dress on a beach).

## 7. How it maps to CaptionForge sections

- **WD14 Tags** section is the primary source — it *is* the SD1.5 caption.
- **JoyCaption / Qwen-VL** NL sections: reference only. Don't feed prose into the
  final caption; at most mine them for a missing tag.
- Final-caption composer: prepend trigger → emit the cleaned WD14 tag list. A good
  SD1.5 project profile keeps captions short and warns on long natural-language
  output.

## Contested / moving

- Whether to caption a *person* set much at all — some report heavy captioning
  slightly *reduces* likeness on medium-quality data, while helping for objects/styles.
- Trigger token choice (rare string vs unique name vs `sks`/`ohwx`).
