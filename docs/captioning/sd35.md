# Captioning for Stable Diffusion 3.5 LoRAs

> Read [00-principles.md](00-principles.md) first. SD3.5 (Large / Medium) is a
> T5-based, natural-language model — but with a hard length ceiling Flux doesn't have,
> and a **much less mature** training ecosystem.

## TL;DR

**Natural-language prose, but kept bounded.** SD3.5 has three text encoders (CLIP-L +
CLIP-G + T5-XXL). Caption in descriptive sentences with solid concrete nouns so all
three encoders get fed — but stay **well under ~256 T5 tokens** to avoid edge artifacts.
LoRA training here is less battle-tested than Flux; treat defaults as unsettled.

## 1. Text encoder & why captioning differs

- **Triple encoder: CLIP-L (77 tok) + CLIP-G (77 tok) + T5-XXL.** Per Stability's card,
  T5 ran at 77/256 tokens across training stages; QK-normalization was added for
  stability across the three.
- The two CLIP encoders respond to keyword/style cues; **T5 carries long descriptive
  semantics.** You *can* route different text to CLIP vs T5 at inference. The ideal
  caption therefore: a **descriptive sentence that also contains concrete nouns / style
  words** so every encoder is fed.
- **256-token T5 artifact:** Stability's card warns that exceeding ~256 T5 tokens can
  produce **edge artifacts** in generations. SimpleTuner historically capped the SD3
  sequence length (e.g. 154, revertible to 77 to save compute at a quality cost). **Keep
  captions comfortably under 256 T5 tokens.**

## 2. Caption style

- Natural-language prose, same tools as Flux (JoyCaption / Florence-2 / Qwen-VL / CogVLM).
- A **prose + a few concrete tags** hybrid is arguably *more* justified here than for Flux
  (two CLIP encoders to feed) — but plain descriptive prose is still the safe default.
- Keep individual captions **tighter than Flux** to respect the 77-token CLIP windows and
  the 256-token T5 ceiling. Don't write 200-word captions for SD3.5.

## 3. Trigger word handling

- Same as Flux: **embed the trigger in a phrase.** Trainers use instance-prompt fields
  (kohya/OneTrainer) or trigger config (ai-toolkit supports SD3.5).
- **Less battle-tested:** Stability did **not** release official training code with SD3.5,
  so trainer implementations vary. Treat trigger/dropout defaults as unsettled.

## 4. Length & detail

Omit-to-bake-in (principles), same as Flux — but the **length ceiling matters more here**.
Don't over-describe: you'll hit the CLIP windows and risk the T5 artifact.

## 5. Do / Don't

**Do**
- Keep captions descriptive but **bounded** (well under 256 T5 tokens).
- Feed all three encoders: prose for T5 + concrete nouns/style words for the CLIPs.

**Don't**
- Don't write long Flux-length captions — the 256-token T5 artifact and 77-token CLIP
  windows punish it.
- Don't assume SD3.5 consensus is as mature as Flux's — it isn't.
- Don't blindly mishandle T5 padding — SimpleTuner changed its default to *stop* zeroing
  T5 padding for SD3.5; padding handling affects results.
- **Training sharp edge:** practitioners report LoRA LR is extremely sensitive (`1e-5`
  fine, `4e-5` can diverge); higher batch sizes help. **Medium** is known to produce
  left/bottom-edge artifacts (OneTrainer issue #651) — use skip-layer guidance at
  inference. Neither is a caption bug, but both muddy evaluation of whether your captions
  "worked."

## 6. Worked example

Style LoRA, token `flatcolorstyle`:

```
flatcolorstyle illustration of a fox sitting on a tree stump in a forest clearing,
viewed from the side, bright midday lighting, simple background.
```

- Deliberately **short** (CLIP windows + T5 ceiling).
- Style token leads; **content fully described** (fox, stump, forest, side view, lighting)
  so the LoRA learns the *style*, not the fox.
- No style adjectives ("flat", "cel-shaded") spelled out — the token owns them.

## 7. Contested / moving

- Exact safe caption length: card says 256 T5; some trainers cap at 154; CLIP windows are
  77. Implementation-dependent — verify your trainer.
- Whole-ecosystem maturity: no official training code means recipes vary and shift.

## 8. How it maps to CaptionForge sections

- Primary: **JoyCaption / Qwen-VL** NL section — but the editor should enforce a **length
  cap** for an SD3.5 profile (warn/trim toward <256 T5 tokens). This is a concrete case
  where the "caption too long" scoring check should be model-aware.
- **WD14 Tags**: optional concrete-noun supplement for the CLIP encoders; keep it short.
- Banned-hedging-phrase checks apply here too (VLM prose).
